# Milestone 9: Product & Model UI

## 1. Overview
A Streamlit-based web interface has been built around the existing frozen M8 pipeline, offering a professional, judge-ready interface for executing predictions and evaluating model artifacts.

## 2. Files Created/Modified
- `src/ui/app.py`: Main Streamlit app entry point with dual-page navigation.
- `src/ui/product_page.py`: Product UI logic for inputting match parameters and rendering predictions.
- `src/ui/model_page.py`: Model UI logic for displaying static M7/M8 validation metrics and global architecture.
- `src/ui/utils.py`: Utility functions for caching data loads and wrapping the `run_prediction` inference flow.
- `tests/ui/test_ui_integration.py`: Integration tests validating that the UI wrappers successfully generate expected pipelines and metrics.
- `README.md`: Appended `streamlit run src/ui/app.py` instructions.

## 3. Pages & Features Implemented
### Part A - Product UI
- **Input Parameters:** Date picker and Team 1 / Team 2 selection dropdowns.
- **Output Rendering:** Displays Expected Team FP, Captain, and Vice-Captain at the top level.
- **SHAP Explanation Drill-down:** For every selected player, an expandable section breaks down exactly why the model chose them. It displays their:
  - `P(play)`
  - `E[FP | play]`
  - `Expected FP`
  - A human-readable text block generated by M8 template logic.
  - The raw SHAP positive/negative factors for BOTH sub-models in two separate tabs.
- **Latency Tracker:** An expandable section at the bottom tracking System Latency, SHAP Explanation Latency, and UI Overhead time for complete transparency.
- **Demo Match**: Defaults inputs to a known holdout match (`2024-07-01`, Malawi vs Kenya) out-of-the-box so reviewers can run the pipeline without configuration hunting.
- **Error Handling**: Captures invalid match inputs (insufficient candidate pool, empty features) and returns actionable UI errors rather than python tracebacks.

### Part B - Model UI (Evaluation View)
- Displays the final `2015-2024` canonical holdout metrics fetched securely from `reports/m7_final_summary.csv`.
- Renders global SHAP model insights from `reports/m8_shap_report.md`.
- Simple textual architecture diagram showing data flow from the Historical Candidate Pool → Feature Engineering → Parallel ML Models → Expected FP → ILP Optimizer → Explainability Layer.

## 4. Test Results
Integration tests (`tests/ui/test_ui_integration.py`) verify the data loading cache and the inference wrappers run seamlessly, ensuring the UI layer hasn't modified underlying prediction behavior.
**All 40/40 pytest cases pass.**

## 5. Latency Tracking
With Streamlit integration, overhead is tracked individually:
- **Total Pipeline Inference:** ~`180-200ms`
- **SHAP Generation (Optional overhead):** ~`150-250ms` 
- **UI Render Overhead:** `<5ms`

## 6. Constraints Verified
- **No Model Changes:** The `model_bundle.pkl` and `play_probability_bundle.pkl` built in M7/M8 remain unchanged.
- **No GenAI/Context Additions:** The UI uses only deterministic models and templates.
- **Strict Pre-toss Logic:** The UI enforces that target predictions cannot ingest post-toss information.

## Conclusion
The Dream11 Next-Gen Team Builder now features a robust graphical frontend. It natively surfaces the system's accuracy and explainability features in a clear, interactive way.
